The useful bits.

$ Command reference

bohselecta popup claude
Open the Ratatui chooser in a dedicated tmux session. Add --model opus or --cwd /path/to/project if needed.
bohselecta preview claude
Open the command-only preview on Sonnet. Use an offered /boh:sonnet, /boh:opus, or /boh:haiku command to continue a saved task.
boh: status
Type inside Claude’s preview to see the configured model, popup or command-only mode, automatic or manual continuation, and why the last task kept its model. No model call is needed.
boh: keep · boh: cancel
Inside either Claude preview, continue a saved task on the current model or discard it. boh: off, boh: on, and boh: status control advice.
bohselecta install claude
bohselecta install codex
Install v0.2.2 native hooks, then restart your client. Codex also requires its normal hook review in /hooks. Change models manually with /model, then resubmit your task. These hooks do not show Ratatui.
bohselecta native status
Check installed hooks, client versions, and catalog freshness. Does not report whether a popup session is open.
bohselecta native refresh claude
Refresh available Claude models without executing a task.
bohselecta history
Review tasks, recommendations, choices, and outcomes. bohselecta history delete ID removes one local record.
bohselecta --help
Explore all commands, including native hook installation and removal.
What happens when I press Enter?+

On Claude Code 2.1.282 and 2.1.283, the popup closes and a helper waits for the matching paused task and an empty prompt, then submits the selected model’s task-bound command. The saved task is claimed once and continues in the same conversation. Other versions display that command for you to enter manually.

Choosing the current model or pressing Escape continues the original prompt. q and Ctrl-C cancel; 45 seconds without a choice also cancels.

No popup? It may already be the right model.+

The preview starts on Sonnet. Ordinary work such as build todo app can run immediately because Sonnet is already the first recommendation. That is quiet routing, not a missing hook.

First type boh: status inside Claude. Ordinary claude and bohselecta preview claude do not open Ratatui. To exercise the chooser, launch bohselecta popup claude --model opus and try an app.

Keep Claude’s pane focused in one writable tmux client, with a terminal at least 46 columns × 15 rows. If the popup cannot open, the hook explains why and preserves the saved-task commands. Check bohselecta history in another terminal to see whether the prompt was recorded.

I chose Sonnet. Why does it still show Opus?+

The selected model applies to that saved task for one turn. Claude’s header or footer can still show the session’s configured default, such as Opus. It does not prove which model served the overridden turn. Later prompts are checked again.

If Claude says “Automatic handoff is not validated,” the task has not continued yet. Enter the exact /boh:sonnet --task … command it displayed, including the task ID. After updating bohselecta, restart bohselecta popup claude: an already-open session keeps its old manual or automatic mode.

Live tests confirmed Sonnet execution on Claude 2.1.282 and 2.1.283 using the synthetic test sessions’ transcripts. Normal completion hooks record the requested model without independently verifying execution identity.

What’s experimental?+

The popup uses version-specific terminal automation, tested with tmux 3.7c. Automatic continuation is enabled only on Claude Code 2.1.282 and 2.1.283; other versions use manual continuation after selection. It does not add a native model-switch API. Don’t type ahead during the handoff; if readiness isn’t confirmed within 12 seconds, use the displayed continuation command.

The model override lasts one turn. Later prompts are checked again. Haiku is excluded in auto and plan permission modes. The popup does not change your saved default or tool permissions.

Why is there still a hook notice?+

Claude displays “Operation stopped by hook” when bohselecta pauses the original prompt to switch models. On validated versions, the popup removes manual command entry, but that client-owned notice and the submitted command remain visible.

Disabled, missing, or timed-out hooks may let Claude continue on its current model. This is model advice, not a guaranteed spending limit.

How does it choose and learn?+

Local rules classify scope and difficulty, filter for sufficient capability, and prefer the lowest configured cost tier. Uncertainty can produce two options. A suitable current model continues quietly.

Rate finished tasks with boh: feedback good, boh: feedback stronger, boh: feedback cheaper, or boh: feedback unsure. Stronger feedback can raise the capability floor. Successful-choice reuse requires matching model evidence; preview completion hooks do not independently verify the execution model.

Does it know actual prices?+

It uses relative cost tiers, not live prices or measured savings. Tier 2 does not mean twice the price of tier 1. Native routing makes no paid classification call.

Dated pricing, token and cache estimates, and separate subscription/API treatment are planned. Switching providers is also future work.

The model catalog is stale. What now?+

Run bohselecta native refresh claude in your shell, then launch the preview again. The preview requires a catalog refreshed within seven days. Refreshing discovers available models without executing your task.

The older v0.2.2 native hooks remain advisory with a stale catalog; they do not provide the preview’s same stop-before-routing behavior.

Where does my data go?+

Task text, context excerpts, outputs, choices, and feedback stay in the local store at ~/.local/share/bohselecta. Files are private to your OS user, not encrypted. Default retention is 90 days. The popup briefly uses a private temporary file with a task excerpt.

Routing is local. When a task continues, Claude sends it through its usual provider and retains its own transcript. Saved continuations expire after 24 hours and are scoped to the same session and folder.

Can I still use normal Claude or Codex?+

Yes. The popup plugin is loaded only for that launch. Exit and open your usual client to return to your existing setup. The command-only Claude preview needs no tmux or Rust.

The v0.2.2 native hooks support both clients with manual model changes and task resubmission. Only the Claude popup on a validated version submits the chosen continuation command for you. In the older native hook flow, use bohselecta: status inside the client; the preview uses boh: status.
